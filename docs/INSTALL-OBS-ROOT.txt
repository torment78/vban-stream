VBAN Stream 0.3.5 - Installation and usage

INSTALLER (STANDARD OR PORTABLE OBS)

1. Close all OBS Studio windows.
2. Run vban-stream-0.3.5-windows-x64-setup.exe.
   Approve the Windows administrator prompt. Protected folders such as
   Program Files need administrator access.
3. Select one option:
   - Standard OBS installation (default): check the detected OBS folder.
     Use Browse if OBS is installed somewhere else.
   - Portable OBS: click Browse and select your portable OBS root folder.
4. Select the folder containing bin, data, and obs-plugins.
   Examples: C:\Program Files\obs-studio or D:\OBS-Portable.
   Do not select bin, 64bit, or obs-plugins themselves.
5. Click Next, review the destination paths, then click Install.
6. Start OBS and open Tools > VBAN Stream Settings.

Both options place the plugin DLL in:
<OBS folder>\obs-plugins\64bit\obs-vban-audio.dll
The data, usage guide and uninstaller go in:
<OBS folder>\data\obs-plugins\obs-vban-audio

The installer requires an existing 64-bit OBS installation. It does not install
OBS or turn portable mode on. Start portable OBS with its usual shortcut or
portable launch option.

If you previously used the root ZIP, select the same OBS folder to update it.
If you used the ProgramData ZIP, first remove that plugin copy to avoid loading
two copies. Standard mode checks the usual ProgramData plugin location.

CHOOSING A MANUAL ZIP

The plugin works with normal and portable OBS Studio on Windows x64.
Both ZIP files contain the same plugin DLL, arranged for different install paths.
Install only one copy.

- vban-stream-0.3.5-obs-root.zip:
  Merge into the OBS installation folder. Works with normal AND portable OBS.

- vban-stream-0.3.5-windows-x64.zip:
  Copy the obs-vban-audio folder into C:\ProgramData\obs-studio\plugins
  for a normal OBS installation.

INSTALL THE OBS-ROOT ZIP

1. Close OBS completely.
2. Open the OBS installation folder, normally:
   C:\Program Files\obs-studio

   For portable OBS, open its own folder instead. The root folder contains
   bin, data, and obs-plugins.

3. Extract the OBS-root ZIP. Copy its obs-plugins and data folders into the
   OBS folder. Merge the folders and accept the administrator prompt if needed.

   The resulting files include:
   <OBS folder>\obs-plugins\64bit\obs-vban-audio.dll
   <OBS folder>\data\obs-plugins\obs-vban-audio\locale\en-US.ini
   <OBS folder>\data\obs-plugins\obs-vban-audio\vban-audio.png

   Do not put the whole extracted package inside obs-plugins or bin.

4. Start OBS and open Tools > VBAN Stream Settings.

INSTALL THE WINDOWS-X64 ZIP

1. Close OBS completely.
2. Extract the windows-x64 ZIP.
3. Copy its obs-vban-audio folder into:
   C:\ProgramData\obs-studio\plugins

   The resulting files include:
   C:\ProgramData\obs-studio\plugins\obs-vban-audio\bin\64bit\obs-vban-audio.dll
   C:\ProgramData\obs-studio\plugins\obs-vban-audio\data\locale\en-US.ini
   C:\ProgramData\obs-studio\plugins\obs-vban-audio\data\vban-audio.png

4. Start OBS and open Tools > VBAN Stream Settings.

For portable OBS, use the OBS-root ZIP instead.

UPDATING OR UNINSTALLING

Close OBS before replacing files. Use the same installation layout as before.
Keep only one installed copy. Existing stream selections and settings are retained.

Installer users: close OBS, then use Windows Settings > Apps > Installed apps >
VBAN Stream for a standard installation. For portable OBS, run unins000.exe
inside <OBS folder>\data\obs-plugins\obs-vban-audio. The uninstaller removes only
its installed files and preserves OBS settings and unrelated files. If you move
the OBS folder, run the installer again for the new location before uninstalling.

Manual ZIP users: close OBS and remove this plugin's DLL and data folder, or its
ProgramData plugin folder, depending on the layout used.

REQUIREMENTS

Windows x64, OBS Studio x64, and the Microsoft Visual C++ x64 runtime.
Tested with OBS 31.1.1 and OBS 32.2.1. The downloads are unsigned.
Use OBS's own libobs, frontend API and Qt DLLs; do not copy development SDK
libraries into an OBS installation.

RECEIVE VIDEO IN OBS

1. On the sending computer, enable a VBAN-Frame output in VoiceMeeter, Matrix,
   or another compatible sender. Choose App View or a display, and JPEG or PNG.
2. Send it to this OBS computer's IPv4 address and UDP listen port (default 6980).
   Audio and video share this port. Use separate video stream names for two views.
3. In OBS, open Tools > VBAN Stream Settings > Video inputs.
4. Enable Video 1 and/or Video 2. Enter each sender's IPv4 address and its exact,
   case-sensitive VBAN stream name. A Friendly name makes it easier to identify.
5. Click Apply. Live status changes to Receiving and shows the resolution/format
   when a complete image has arrived and decoded.
6. In the OBS Sources panel, click + > VBAN Video. Choose the configured video.
   Add another VBAN Video source to display the second view. Resize/crop normally.

There are two independent video inputs in addition to the eight audio inputs.
JPEG and PNG are detected automatically. Each image can be up to 4096 x 2160,
including portrait orientation within the same pixel limit. PNG transparency is
preserved. Images stay in their original colours; the setup window is dark.
Before reception, the source shows a black 1280 x 720 picture. It uses the image's
native dimensions after reception. After three seconds without a complete image,
it goes black while retaining the last dimensions, and recovers automatically.

Video sources contain no audio. Add the normal VBAN Stream audio source if needed.
Each video input has its own Mouse control card, disabled initially.

If Waiting continues, match the sender IP, stream name and shared UDP port, and
allow incoming UDP for OBS on your LAN. Hover over Live status for decoded frames,
incomplete frames, decode errors and queue drops. Lost/incomplete images are
skipped instead of shown partially. If these counters keep increasing, try a lower
frame rate/resolution or JPEG instead of PNG, and check the network connection.

RECEIVE AUDIO IN OBS

1. Open Tools > VBAN Stream Settings.
2. Enter the computer SENDING audio to OBS in Common sender IPv4.
   Turn off common-IP mode to use a separate sender address for each slot.
3. Set UDP listen port. The default is 6980.
4. Enable the slots you need.
5. Enter each VBAN stream name exactly as it appears on the sender.
   Names are case-sensitive, with 1 to 16 printable ASCII characters.
6. Enter an optional Friendly name, such as Microphone or Game Audio.
7. Click Apply.
8. On the sender, configure VBAN output to this OBS computer's IPv4 address
   and the same UDP port.
9. In an OBS scene, choose Sources > + > VBAN Stream.
10. Select the configured stream from VBAN Stream.

Each named stream automatically receives 1 to 8 audio channels. No channel-count
selection is needed. The eight slots are separate streams; each can carry up to
eight channels. One source still appears as one mixer fader.

To retain eight channels in OBS, set Settings > Audio > Channels to 7.1 and use an
output or recording format that supports it. Stereo OBS output downmixes the
incoming channels. Seven-channel input pads channel 8 with silence.
The two monitor returns are stereo.

The source appears in the OBS Audio Mixer. Automatically named sources use
the slot's Friendly name. Names you assign yourself are preserved.
Use normal OBS faders, mute, filters, monitoring and track controls.
Multiple OBS sources can select the same slot.

Configure a sender/stream-name pair only once in the global slots.
Other enabled slots need different sender/name combinations.

RECEIVE STATUS

The Channels box shows the actual incoming channel count (1 to 8) for each
receiving stream. Input format shows its PCM bit depth or floating-point format.
These describe the incoming stream before OBS downmixing. Waiting, disabled,
error or timed-out streams show a dash instead of stale values.
Receiving: N / 8 streams counts live configured streams, not audio channels or
multiple OBS source copies of the same stream.

Receiving: matching valid packets arrived recently.
Waiting: no recent matching valid packets.
Error: invalid/unsupported audio or a receiver/socket error.
Disabled: the slot is disabled.

Hover over status in the settings window for details. In source Properties,
use Refresh status to update counters. The stream dropdown is not rebuilt
periodically while you are selecting a stream.

SEND THE OBS MONITOR MIX BACK

1. Open Tools > VBAN Stream Settings > VBAN RETURNS.
2. In Send from this PC, select this OBS computer's LAN address and adapter.
   Select the address belonging to the computer, not its gateway/router.
   Automatic lets Windows choose the route.
3. Enable Return 1 and/or Return 2.
4. Choose PCM 16-bit or PCM 24-bit in the PCM format dropdown for each return.
   The choice is independent for each destination. Existing settings keep 24-bit.
5. Set Destination IPv4 to the computer RECEIVING that return.
6. Set UDP port to the receiving computer's VBAN input port.
7. Choose a VBAN stream name, such as OBSRETURN1 or OBSRETURN2.
8. Leave Return audio buffer at 60 ms initially.
9. Click Apply to save and use the selected formats.
10. In OBS Advanced Audio Properties, set each desired source to Monitor Only
    or Monitor and Output. Monitor Off removes it from the return.
11. In VoiceMeeter's incoming VBAN settings, enable the stream and match
    its name, receiving port and sender IP (the OBS computer's address).
    Route the incoming stream to the desired VoiceMeeter output.

Both returns contain the same stereo monitoring mix in their selected PCM format.
The sample rate still follows OBS: keep OBS at 48 kHz for 48 kHz returns. Choosing
16-bit or 24-bit does not change it. Source filters and fader gains are included.
Destinations and packet counters are independent. Each enabled return sends silence if there is no
monitored audio.

In Windows OBS 32.2.1, program mute does not mute headphone monitoring.
Use Monitor Off to exclude a source from the return. Tested OBS 31.1.1
monitoring honors the mute flag.

Sending means Windows accepted outgoing packets. It does not confirm reception.
The actual local source and destination addresses are displayed beside each
return. These are the socket addresses before any router/NAT translation.
An unavailable selected adapter produces an error without silently changing it.
Reopen settings to refresh the adapter list.

Never feed a received OBS return into a VBAN stream that comes back into OBS.
That creates an audio feedback loop.

MOUSE RETURN FROM OBS PROGRAM

1. Receive the remote VoiceMeeter App View as a VBAN Video source in your scene.
2. On the remote computer, enable an incoming VBAN-TEXT stream. Set its sender IP
   to the OBS computer and choose a name such as Command1. Right-click its format
   or sample-rate field and enable Manage Mouse command.
3. Open Tools > VBAN Stream Settings > Video inputs. Under the matching video,
   enable its Mouse control card. Enter that computer's IP, VBAN UDP port and the
   exact incoming command stream name. The command name is separate from video.
4. Select the local LAN adapter under Mouse control: send from this PC if needed. Click Apply.
5. Enable OBS Studio Mode. Hold Ctrl while left/right-clicking or dragging inside
   the live App View in the Program pane. On Mac use the physical Control key.
   Preview remains for editing the scene.

Mouse return is disabled initially. Each video has its own destination.
Scene positioning, scaling, manual cropping, rotation, groups and nested scenes
are supported. Keep the sender's App View at its original size. Visible overlays
block clicks through them; filters and Crop to Bounding Box disable interaction.
Release Ctrl, press Esc, or leave the picture to end a drag. Changing scenes,
leaving Studio Mode, losing focus or losing video also releases the remote button.
Typing, mouse wheel, projectors and fullscreen Program are not supported.
Sent counts accepted outgoing UDP packets; it does not confirm remote reception.
This is a preview feature. Test it with your VoiceMeeter version before live use.

SEND OBS PROGRAM TO VBAN FRAME

1. Open Tools > VBAN Stream Settings > OBS to VBAN Frame.
2. Enable Send OBS Program. Enter the receiving computer's IPv4 address,
   UDP listen port and exact incoming video stream name.
3. Select this OBS computer's LAN adapter if needed. Start with JPEG,
   a 1280 x 720 resolution limit, 15 fps, quality limit 80 and 24 Mbps.
   Leave Adapt JPEG quality to maintain frame rate checked initially.
4. Click Apply. In VBAN-Screen or another VBAN-Frame receiver, match the
   OBS sender IP, video stream name and UDP port.

The output follows live Program, including scene changes and transitions.
Studio Mode is optional for video sending. The OBS interface, Preview and
audio are not included. Use a separate monitor return for sound.
The resolution limit preserves aspect ratio and never enlarges the image.
Adaptive JPEG lowers quality when needed to fit the FPS and network limit.
The quality setting is its maximum; uncheck adaptation to keep fixed quality.
For lower traffic, try 12 or 6 Mbps, then lower resolution or FPS if too soft.
The network limit is this stream's budget, not the speed of your LAN.
Static pictures use a cached refresh roughly once per second.

JPEG and PNG encoding use the CPU. PNG stays lossless but is larger and slower
for detailed moving pictures; JPEG is the better starting point for motion.
FPS is an upper limit. Encoding, image size and receiver speed affect actual FPS.
Queued old pictures are skipped to avoid a growing delay.

Output is disabled initially and currently requires SDR video in OBS.
Disable it and click Apply before changing OBS video settings or profiles.
Live status shows measured outgoing FPS, estimated Mbps including packet overhead,
and the actual JPEG quality. Low FPS is normal for a still picture. Hover for
encode time, send time, capture-to-send age and error counters. These measure local
work; Sending does not confirm remote reception or display. Compare with the
receiver when motion looks slow. Reduce resolution, FPS or fixed JPEG quality if
frames are repeatedly skipped. For an image-budget error, use JPEG, lower
resolution or a higher network limit if your LAN allows it.
Avoid including the received copy in the same outgoing Program scene.

RETURN AUDIO BUFFER AND DIAGNOSTICS

Return audio buffer is adjustable from 20 to 200 ms, default 60 ms.
This gives source audio time to reach the mixer before transmission.
Increasing it adds monitor delay. Try 100 ms if Late audio frames keeps
increasing during steady playback.

Negative audio/video sync offsets add shared waiting time to preserve relative
alignment. OBS monitoring sync behavior differs for video and audio-only sources.
The final physical headphone-device buffer is separate from this network return.

Hover over return status for:
- Capture queue overflows: the worker could not keep up with captured audio.
- Queue peak: busiest source's peak occupancy out of 128 capture blocks.
- Late audio frames: source data missed the return mixing deadline.
- Clock corrections: normal small source-clock adjustments.
- Clock discontinuities: source timestamps jumped or restarted.
- Clipped samples: the combined mix exceeded full scale. Lower source faders.
- Invalid float samples: a source or filter supplied invalid audio.
- Socket errors: Windows rejected an outgoing UDP packet.
- Send gaps: the local transmitter paused for more than 20 ms.
- Windows audio priority: whether multimedia scheduling is available.

Compare counter changes during steady playback, after startup or settings edits.
Audio counters follow current source lifetimes. Return Apply resets send and
clipping counters. No local counter proves remote packet delivery.

VoiceMeeter's incoming VBAN network buffer is configured separately on the
receiving computer. If local counters stay steady but VoiceMeeter reports
reception errors, check its VBAN network-quality setting and the network path.
An upstream input stream can also contain gaps or clicks before the return mix.

TROUBLESHOOTING

If the plugin is missing, check the exact DLL path, x64 architecture and the
OBS startup log for obs-vban-audio. Restart OBS after installing it.

If a stream remains Waiting, check sender IP, stream name, destination IP,
UDP port, enabled VBAN output and inbound Windows Firewall permissions.
Another receiver may already own the chosen listen port.

For LAN returns, select the physical LAN adapter if VPN routing selects an
unexpected path. The plugin does not change firewall, router or VPN settings.

If audio clips, lower the contributing source faders. Their sum can exceed
full scale even when each individual source is below it.

Missing input packets cannot be recreated by increasing the return buffer.
Check both the OBS receive counters and VoiceMeeter's return-reception indicators.

Settings are saved in settings.json in the OBS module configuration folder.
Source stream selections are saved by OBS with the scene collection.

VIDEO TRANSFER
JPEG is compressed on the CPU. Quality 100 can produce large images, and each
changing picture is sent as a complete JPEG. Version 0.3.5 spaces individual
packets across the frame interval to reduce bursts at the receiver. JPEG file-size optimization
retains the selected quality. Check actual playback and errors on the receiver.
Mbps means megabits per second: 80 Mbps is about 10 megabytes per second.
Zero sender errors do not prove that the receiver received a complete picture.
